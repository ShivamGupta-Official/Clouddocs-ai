Kubernetes Production Architecture & Operations Handbook

1. Core Architecture and Primitive Concepts
In Kubernetes, a Pod represents a single instance of a running process in your cluster and is the smallest deployable unit of computing. Pods contain one or more containers, storage resources, and a unique network IP.

2. Workload Controllers
- Deployments: Provide declarative updates for Pods and ReplicaSets. They handle rolling updates, rollbacks, and scale replicas seamlessly.
- StatefulSets: Manage stateful applications that require unique network identifiers and persistent disk storage (e.g., PostgreSQL or MongoDB).
- DaemonSets: Ensure that all (or some) nodes run a copy of a Pod (e.g., Fluentd for log collection or Prometheus node-exporter).

3. Service Discovery and Networking
- ClusterIP: Exposes the Service on a cluster-internal IP. This makes the Service only reachable from within the cluster.
- NodePort: Exposes the Service on each Node's IP at a static port (between 30000 and 32767).
- LoadBalancer: Exposes the Service externally using a cloud provider's load balancer (e.g., AWS NLB/ALB).
- Ingress: An API object that manages external access to the services in a cluster, typically HTTP/HTTPS, providing name-based virtual hosting and URI routing.

4. Resource Management and Limits
Every container should have resource requests and limits configured:
- CPU: Measured in millicores (500m = 0.5 CPU core).
- Memory: Measured in bytes or mebibytes (e.g., 256Mi, 1Gi). If a container exceeds its memory limit, the Linux kernel terminates it with an OOMKilled (Out Of Memory) event.
